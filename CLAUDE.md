# Карта проекта

## Что это
Лендинг и MVP идеи «Набор маленьких QA-инструментов» (идея 5 из `StartUp/yc-rfs/product-ideas.md`). Тестировщик каждый раз собирает чек-листы с нуля и пишет баг-репорты руками. Страница за десять секунд объясняет это и сразу даёт попробовать инструменты прямо в браузере, без регистрации и сервера:

- генератор чек-листа по описанию фичи (работает по ключевым словам, можно добавить свои правила под проект);
- шаблон баг-репорта: форма, на выходе текст для Jira или CSV;
- пакет проверок на спринт: несколько фич в столбик, чек-лист по каждой и один общий CSV для Excel.

Главный критерий успеха: инструмент подстраивается под любой проект. Данные не уходят из браузера. Подробности и решения: `docs/superpowers/specs/`.

## Что где лежит
- `index.html` — весь сайт одним файлом (стили и скрипт внутри, без библиотек и сборки);
- `tests/run.js` — тесты чистых функций, запуск: `node tests/run.js`;
- `docs/superpowers/specs/` — документы дизайна (что и зачем делаем, решения);
- `docs/superpowers/plans/` — планы реализации;
- `docs/agents/` — настройки для скиллов (где задачи, какие метки, где словарь);
- `.superpowers/` — служебная папка черновиков, в git не попадает.

## Как сайт публикуется
Сайт хостится на GitHub Pages из репозитория `ol0710/qa-tools-landing`: после `git push` в ветку `master` GitHub сам обновляет страницу, через минуту-две. Статус на 29.10.2026: Pages в репозитории ещё не включены (Settings → Pages → Deploy from a branch → `master` / `/ (root)`), без этого пуш сайт не обновит.

## Как мы работаем
Одна задача на GitHub (Issue) = одна новая сессия Claude. Берём задачу, открываем чистую сессию, делаем, коммитим, пушим, закрываем задачу. Не смешиваем несколько задач в одной сессии.
