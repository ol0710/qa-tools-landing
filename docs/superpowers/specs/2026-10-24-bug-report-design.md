# Шаблон баг-репорта: короткий дизайн

Дата: 2026-10-24. Дополняет `2026-10-23-landing-design.md`: второй рабочий инструмент вместо карточки «скоро».

## Зачем
Тестировщик пишет баг-репорты руками и вставляет в Jira (иногда в Excel). Форма собирает поля в готовый текст за секунды.

## Цели
- Форма из шести полей: заголовок, окружение, шаги, ожидаемый результат, фактический результат, серьёзность.
- Выход 1: обычный текст с подписями для Jira, кнопка «Скопировать».
- Выход 2: файл `.csv` для Excel, одна строка на баг, поля в столбцах.
- Работает в браузере, данные никуда не уходят, без внешних библиотек.

## Не цели
- Разметка Jira (Markdown, wiki): выбран обычный текст, он выглядит нормально везде.
- Вложения, предусловия, приоритет, версия сборки, сохранение черновиков.
- Отправка в Jira напрямую.

## Решения Ольги
- Формат для Jira: обычный текст с подписями, без разметки.
- Второй выход: CSV для Excel.
- Состав полей: средний набор (6 полей выше).

## Подход (мой выбор)
Один подход: форма в том же `index.html`, чистые функции `buildBugReportText(fields)` и `bugReportToCsv(fields)` рядом с остальными, DOM-обвязка внизу, тесты в `tests/run.js`. Отдельной страницы или файла нет: это противоречит ограничению «один файл».

## Детали
- **Место на странице:** новая секция `#bug` сразу после `#tool`, перед блоком про боль. Из секции `#soon` карточка «Шаблон баг-репорта» убирается, остаётся карточка «Калькулятор покрытия».
- **Поля:** «Заголовок» (однострочное), «Окружение» (однострочное, пример `Chrome 126, Windows 11`), «Шаги» (по одному на строку), «Ожидаемый результат», «Фактический результат» (многострочные), «Серьёзность» (список: Блокирующая, Критичная, Значимая, Незначительная, Тривиальная; по умолчанию Значимая). Примеры серым в каждом поле. Видимые подписи над полями.
- **Текст для Jira:** строки вида `Заголовок: ...`, `Серьёзность: ...`, `Окружение: ...`, затем `Шаги:` с нумерацией `1.`, `2.` (пустые строки пропускаются), затем `Ожидаемый результат: ...`, `Фактический результат: ...`. Пустые необязательные поля пропускаются.
- **Обязательные поля:** заголовок, шаги, фактический результат. Без них кнопка выдаёт подсказку «Заполните заголовок, шаги и фактический результат», ничего не показывает.
- **CSV:** BOM, разделитель `;`, строка заголовка `Заголовок;Серьёзность;Окружение;Шаги;Ожидаемый результат;Фактический результат`, одна строка данных. Шаги в одной ячейке через перевод строки, ячейка в кавычках. Защита от формул (`=`, `+`, `-`, `@`) и экранирование как у чек-листа, общая функция.
- **Копирование:** `navigator.clipboard.writeText`; если недоступно, выделить текст в поле результата и показать подсказку «Выделено, нажмите Ctrl+C».
- **Безопасность:** весь вывод через `textContent`.

## Оставлено исполнителю
- Формулировки подсказок, цвета и отступы в рамках тёмной темы.
- Порядок полей на телефоне (одна колонка, поля на всю ширину).

## Проверка
- Тесты на обе функции: нумерация шагов, пропуск пустых строк, пустые необязательные поля, экранирование `;` и `"` и защита от `=`, обязательные поля.
- Руками на 375px: нет горизонтальной прокрутки, копирование работает, CSV открывается в Excel.
