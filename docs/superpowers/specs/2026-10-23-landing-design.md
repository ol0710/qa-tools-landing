# Лендинг «Набор маленьких QA-инструментов»: документ дизайна

Дата: 2026-10-23. Идея 5 из `StartUp/yc-rfs/product-ideas.md`.

## Зачем это нужно

Тестировщик каждый раз собирает чек-листы и тест-кейсы с нуля и пишет баг-репорты руками. Ему нужно убыстрить рутину. Лендинг за десять секунд объясняет, что это, для кого и зачем, и сразу даёт попробовать инструмент, ничего не открывая и никуда не переходя.

Вторичная польза (из `product-ideas.md`): страница служит доказательством навыка Ольги для работодателей. Страница делается для тестировщика, а не для работодателя.

## Цели

- За десять секунд понятно: это генератор чек-листа для тестировщика.
- Главное действие: человек сразу пробует инструмент прямо на странице.
- Инструмент адаптируется под любой проект. Это критерий успеха по словам Ольги: «если инструмент можно адаптировать под любой проект, это успех».
- Результат можно выгрузить и открыть в Excel.
- Страница нормально выглядит и работает с телефона.

## Не цели

- Нет серверной части, ИИ, регистрации, аналитики, сбора почты.
- Шаблон баг-репорта и калькулятор покрытия на странице не работают, только показаны карточками «скоро».
- Нет настоящего `.xlsx` (см. «Выгрузка»).
- Нет экспорта и импорта пользовательских правил и кнопки копирования результата.

## Анти-цели (провал, даже если технически всё работает)

- Инструмент выдаёт общий бесполезный набор на любое нестандартное описание, и тестировщик видит, что он не его.
- Страница обещает больше, чем умеет (например, «ИИ понимает вашу фичу»). Генератор работает по ключевым словам и шаблонам, и на странице это нельзя маскировать.
- Маркетинговый шум вместо конкретики.

## Ограничения

- Один файл `index.html` прямо в `StartUp/landing`, стили и скрипт внутри.
- Без внешних библиотек, шрифтов и картинок из интернета. Шрифты только системные.
- Ванильный JS, без сборки.
- Данные пользователя не уходят из браузера.
- Нормально выглядит с телефона.
- Проект в `StartUp/landing`. Git-репозиторий там уже создан (`git init` выполнен), коммитов пока нет. Папка `.superpowers/` исключена в `.gitignore`.

## Подходы

Здесь по сути один разумный путь, потому что ограничения сужают выбор.

- **Выбран:** один файл, генератор как данные + короткая функция. В начале скрипта таблица «ключевое слово → набор проверок», ниже функция, которая сопоставляет описание с таблицей. Новые правила добавляются записью в таблицу без правки логики. Если ни одно ключевое слово не найдено, выдаётся общий набор.
- **Отклонён:** жёсткие `if/else` в логике. Результат тот же, но каждое новое правило приходится вписывать в код, а адаптируемость (цель успеха) была бы невозможна.
- **Отклонён:** отдельные `style.css` и `app.js`. Противоречит условию «один файл, стили внутри», выигрыша для страницы такого размера нет.
- **Отклонён:** генерация через ИИ. Нужен сервер и ключ, это отдельный проект, а не статическая страница.

Это выбор исполнителя дизайна (Claude), не решение Ольги.

## Решения Ольги

- Аудитория: тестировщик, которому нужно убыстрить рутину.
- Главное действие: сразу открыть инструмент и попробовать.
- Инструмент один, прямо на странице: генератор чек-листа по описанию фичи. Два остальных инструмента (шаблон баг-репорта, калькулятор покрытия) показаны карточками «скоро».
- Тон: деловой, коротко, без воды.
- Блоки сверху вниз: заголовок → инструмент → боль/решение → «скоро» → подвал.
- Первый экран: одна колонка по центру. Заголовок, под ним поле ввода и кнопка, ниже результат. Вариант B из трёх показанных макетов.
- Стиль: тёмная тема. Тёмный фон (около `#0f172a`), светлый текст, одна зелёная кнопка (около `#22c55e`) как в показанном макете «тёмный, как в терминале». Сначала был выбран светлый вариант, затем Ольга сменила решение на тёмный, зная его недостаток: хуже читается при ярком свете (например, на телефоне на солнце). Нужен достаточный контраст текста.
- Логика генератора: по ключевым словам и шаблонам.
- Выгрузка в Excel: CSV.
- Адаптация: тестировщик добавляет собственные правила «ключевое слово → проверки» прямо на странице. Правила хранятся в `localStorage` его браузера.

## Детали дизайна

### Первый экран
Заголовок про чек-лист из описания фичи (формулировку подбирает исполнитель, в деловом тоне, например «Чек-лист по описанию фичи за секунды»). Под заголовком текстовое поле «Описание фичи», кнопка «Собрать чек-лист», под ней область результата. Результат появляется на месте без перехода на другую страницу.

### Результат
Список пунктов-проверок, сгруппированный по найденным темам. Рядом с результатом кнопка «Скачать для Excel».

### Выгрузка в Excel
Настоящий `.xlsx` без библиотек невозможен (это zip-архив). Поэтому: файл `.csv`, кодировка UTF-8 с BOM (метка порядка байтов), разделитель `;`, чтобы русский Excel правильно показал буквы и столбцы. Кнопка и подпись называют файл `.csv`, а не `.xlsx`. Столбцы — на усмотрение исполнителя (минимум: номер, проверка, статус).

### Свои правила
Раздел на странице, где тестировщик вводит ключевое слово и список проверок, и они добавляются к встроенной таблице. Хранятся в `localStorage`. Если `localStorage` недоступен, страница работает без сохранения правил и один раз сообщает об этом. Правила можно удалить.

### Боль и решение
Короткий блок: сейчас чек-листы и тест-кейсы собираются с нуля и вручную, инструмент даёт стартовую заготовку, которую можно настроить под проект.

### Карточки «скоро»
Две карточки (шаблон баг-репорта, калькулятор покрытия), без кликабельных ссылок.

### Подвал
Минимальный, без сбора данных.

## Мои решения по деталям (не решения Ольги, можно поменять)

- **Сопоставление ключевых слов:** без учёта регистра, «ё» считается «е», поиск по началу слова (основе), чтобы «пароль», «пароля», «паролем» срабатывали на «парол». Ключевые слова русские и английские. Одно описание может сработать на несколько тем сразу.
- **Свои правила:** ключевые слова вводятся через запятую, проверки по одной на строку. Сопоставление то же, что у встроенных. Название группы — первое ключевое слово.
- **Совмещение:** пользовательские правила дополняют встроенные, повторы убираются. Общий набор по умолчанию выдаётся, только если не сработало ни одно правило (встроенное или своё).
- **Статус в CSV:** столбец «Статус» со значением «не проверено». Интерактива статуса на странице нет, только отображение пунктов с пустыми чекбоксами. Группа — отдельный столбец.
- **Пустой ввод:** кнопка ничего не выводит и показывает подсказку «Опишите фичу».
- **Объём данных:** примерно 8–12 встроенных тем по 4–8 проверок, общий набор 5–8 пунктов.
- **Потеря правил:** рядом с разделом «Свои правила» одна строка, что они хранятся только в этом браузере.
- **Общий набор:** одна группа «Общие проверки».

## Что оставлено исполнителю

- Точные формулировки заголовка и текстов (в деловом тоне).
- Начальный набор встроенных ключевых слов и проверок (форма, поле, пароль, загрузка файла, оплата, поиск и подобное) и общий набор по умолчанию.
- Столбцы CSV сверх минимума.
- Точные цвета, отступы, размеры в рамках тёмной темы (тёмный фон, одна зелёная кнопка), при достаточном контрасте текста.
- Подпись автора в подвале, если нужна.

## Проверка результата

- Страница открывается из файла и работает без интернета.
- Ввод описания с ключевым словом даёт соответствующие проверки, без ключевых слов даёт общий набор.
- Добавленное пользовательское правило срабатывает и остаётся после перезагрузки.
- CSV открывается в Excel с правильными русскими буквами и столбцами.
- На экране телефона нет горизонтальной прокрутки, кнопки и поле удобно нажимать.
