# Отчёт по качеству спринта: документ дизайна

Дата: 2026-11-01. Дополняет `2026-10-29-sprint-pack-design.md`: пакет проверок на спринт из заготовки превращается в рабочий инструмент, по которому ведут тестирование и собирают отчёт.

## Зачем это нужно

Сейчас пакет на спринт только выдаёт список проверок и CSV с пустым статусом. Но у тестировщика работа на этом не заканчивается: несколько дней он гоняет проверки, а в конце спринта должен показать руководителю, что получилось. Новая часть закрывает этот конец: прямо в пакете отмечаются результаты, и из них собирается отчёт по качеству, который скачивается для Excel.

Выбор Ольги: результаты вводятся прямо в пакете (а не вручную в форму отчёта и не вставкой выгрузки из Jira), пакет и отметки переживают перезагрузку, отчёт нужен в Excel.

## Цели

- Каждая проверка в пакете кликабельна и имеет статус. К любой проверке в любом статусе можно дописать комментарий.
- Пакет, статусы и комментарии сохраняются в браузере: закрыл вкладку вечером, утром продолжил с того же места.
- Под пакетом показывается отчёт по качеству: общая строка с цифрами, таблица по фичам, список комментариев. Отчёт обновляется сразу при каждой отметке.
- Два файла для Excel: пакет (со статусами и комментариями) и отчёт (сводка по фичам).
- По-прежнему без сервера, регистрации и внешних библиотек.

## Не цели

- Нет истории и сравнения спринтов, нет нескольких пакетов одновременно: в браузере живёт один пакет.
- Нет переноса между компьютерами: ни входа в аккаунт, ни выгрузки и загрузки прогресса файлом.
- Нет импорта результатов из Jira, TestRail, Excel.
- Нет настоящего `.xlsx`, PDF и печати, только CSV. Скопировать текст отчёта в письмо тоже не предусмотрено.
- Нет вердиктов вроде «релиз можно / нельзя», порогов, цветовых оценок «хорошо / плохо» и оценок времени.
- Нет привязки комментария к баг-репорту и создания багов из упавшей проверки.

## Анти-цели (провал, даже если технически всё работает)

- Отметки молча теряются: после «Собрать пакет», добавления правила, перезагрузки или правки текста в поле фич ранее выставленные статусы и комментарии пропали, хотя человек этого не просил.
- Цифры в отчёте расходятся с тем, что видно в пакете, или с файлом CSV.
- Статус различим только цветом (человек не различает цвета или смотрит с телефона на солнце).
- В отчёте появляются придуманные цифры: оценка времени, «качество продукта N из 10», любые числа, которых нет в отметках человека.
- Новая часть ломает уже работающие блоки: генератор чек-листа, баг-репорт, «Свои проверки», и скачивание пакета, как оно было.

## Ограничения

- Те же, что у пакета: один файл `index.html`, ванильный JS, без сборки и сети, тёмная тема, одна зелёная кнопка, без горизонтальной прокрутки на 375px, вывод в DOM через `textContent`.
- Чистые функции рядом с остальными, тесты в `tests/run.js`, запуск `node tests/run.js`.
- Данные остаются в браузере. Хранилище `localStorage` недоступно: всё работает, пока страница открыта, и показывается то же предупреждение, что и у правил.
- CSV как у существующих: BOM, разделитель `;`, общая `csvCell` с защитой от формул (комментарии тоже проходят через неё).

## Подходы

Решалось, как отдавать результат в Excel. Три варианта:

- **Выбран 1: два CSV.** Существующий файл пакета получает колонки «Статус» (текущий, а не вшитое «не проверено») и «Комментарий». Новая кнопка выгружает отчёт: таблица по фичам и строка «Итого». Короче всего, повторяет то, что уже работает и проверено тестами. Минус: файла два, оформления (цвета, ширина колонок) нет.
- **Отклонён 2: один CSV, сводка сверху, подробности ниже.** Excel не умеет фильтровать и сортировать такую смесь, для отчёта руководителю выглядит неряшливо.
- **Отклонён 3: настоящий `.xlsx` с листами «Отчёт» и «Проверки».** Самый аккуратный результат, но нужна библиотека или ручная сборка архива, и проверить файл в настоящем Excel здесь нельзя, риск «битого» файла выше. Можно сделать позже отдельной доработкой, данные для неё уже будут готовы.

Вид отчёта: из двух макетов (A — короткая сводка, B — подробно по фичам) выбран **B**.

## Решения Ольги

- Результаты отмечаются прямо в пакете на спринт.
- Статусы: «не проверено», «прошла», «упала», «пропущена», «заблокирована».
- Комментарий можно дописать к любой проверке, в любом статусе.
- Пакет, статусы и комментарии хранятся в браузере и переживают перезагрузку. Перенос между компьютерами не нужен.
- Вид отчёта: B, подробно по фичам (общая строка с цифрами, таблица по фичам, комментарии).
- Экспорт: два CSV для Excel.

## Детали дизайна

### Проверка в пакете
У каждой проверки видны её текст, кнопка статуса и кнопка комментария. Квадратик ☐, нарисованный стилем, для пакета убирается: вместо него настоящая кнопка. Кнопка статуса показывает значок и слово, не только цвет. Клик переключает по кругу: не проверено → прошла → упала → заблокирована → пропущена → не проверено. Кнопка комментария раскрывает поле ввода; если комментарий есть, это видно и при свёрнутом поле.

### Отчёт
Под результатом пакета, по формату макета B:
- Общая строка: всего проверок, и сколько прошли, упали, заблокированы, пропущены, не проверены.
- Таблица по фичам: по строке на фичу, колонки с числами по статусам и «Готовность». Готовность фичи = прошли ÷ все проверки фичи, округление до целого процента. Заблокированные и непроверенные проверки тянут цифру вниз, это сделано намеренно.
- Список комментариев: каждая проверка с непустым комментарием, любого статуса: фича, статус, текст проверки, комментарий.
- В отчёт и в счётчики идут только фичи, для которых есть правила (как в CSV пакета). Фичи без правил в отчёте не участвуют.
- Пока не отмечено ничего, отчёт показывает нули и одну строку-подсказку «Отметьте результаты проверок, и здесь появится отчёт». Скрывать его не нужно.

### Файлы для Excel
- «Скачать пакет для Excel (.csv)»: существующая кнопка. Столбцы: №; Фича; Группа; Проверка; Статус; Комментарий.
- «Скачать отчёт для Excel (.csv)»: новая кнопка. Таблица по фичам с теми же цифрами и «Готовностью» плюс последняя строка «Итого». Комментарии в этот файл не входят, они в файле пакета.

### Сохранение
Одно значение в `localStorage` (ключ отдельный от `qa-custom-rules`): список фич и отметки. После загрузки страницы поле «Фичи спринта» заполняется сохранённым списком, пакет собирается заново по текущим правилам, отметки применяются. Сохраняется после каждого клика и каждого изменения комментария.

## Мои решения по деталям (не решения Ольги, можно поменять)

- **Ключ отметки:** фича + группа + текст проверки. Если после добавления правила состав проверок фичи изменился, отметки совпадающих проверок сохраняются, у новых статус «не проверено». Отметки проверок, которых больше нет, остаются в хранилище и не показываются.
- **Кнопка «Собрать пакет» не стирает отметки.** Повторная сборка по тому же или изменённому списку сохраняет отметки у совпавших ключей. Сбрасывать их нужно только явно.
- **Кнопка «Начать заново»** очищает все статусы и комментарии. Перед этим спрашивает подтверждение через `confirm()`, потому что действие необратимо. Список фич не трогает.
- **Отметки сами не удаляются никогда.** Они хранятся по названию фичи (а не привязаны к текущему списку) и стираются только кнопкой «Начать заново». Поэтому «Показать на примере», удаление фичи из поля и пересборка не уничтожают прогресс: вернул фичу в список, отметки на месте. Хранилище при этом ограничено: не больше 10 фич в пакете, комментарий до 500 знаков, объём ничтожный.
- **Что сохраняется как список фич:** текст поля «Фичи спринта» как человек его ввёл. При загрузке страницы он подставляется в поле и пакет собирается заново.
- **Одинаковые проверки внутри фичи** (два правила дали одну и ту же строку в одной группе) в пакете схлопываются в одну, так что ключ «фича + группа + текст» однозначен, а цифры отчёта совпадают с файлами. Одинаковые названия фич уже схлопываются разбором поля (регистр и пробелы не различаются).
- **Источник цифр один:** и счётчики на странице, и отчёт, и оба CSV считаются из одного и того же собранного пакета с отметками. Строка «4 фичи, 23 проверки» под пакетом остаётся как есть (про фичи и проверки), а статусы показывает только отчёт.
- **«Итого» в CSV отчёта и общая строка на странице:** готовность = прошли ÷ все проверки всех фич с правилами (общий процент, не среднее по фичам).
- **Кнопка «Скачать отчёт для Excel»:** доступна всегда, пока в пакете есть хотя бы одна фича с правилами; пока ничего не отмечено, в файле нули. Подсказку «Отметьте результаты…» показываем, только если нет ни одного статуса, отличного от «не проверено», и ни одного комментария. Комментарий к непроверенной проверке разрешён и попадает в список комментариев.
- **Последовательность статусов:** по кругу кликом, а не выпадающим списком. Минус: до четырёх кликов до нужного статуса. Если на телефоне будет неудобно, заменить на выпадающий список.
- **Порядок колонок таблицы отчёта:** Фича; Прошли; Упали; Заблокированы; Пропущены; Не проверено; Готовность. На 375px допустимо сократить заголовки.
- **Длина комментария:** не больше 500 знаков, лишнее обрезается.
- **Пустые фичи без правил** в отчёте не показываются, как и раньше в CSV.
- **Хранилище недоступно:** работает в памяти, показывается то же предупреждение, что и у правил.
- **Битые данные в хранилище** (не JSON, не тот формат): игнорируются, страница стартует с пустого пакета, ничего не падает.

## Что оставлено исполнителю

- Значки и формулировки статусов, заголовок отчёта, подсказки (в деловом тоне).
- Как именно перерисовывать: сейчас перерисовывается только фича, у которой изменился состав проверок (`refreshSprintAfterRule`), и это не должно стирать комментарий, который человек сейчас вводит.
- Как перестроить `renderResult` для пакета (сейчас он строит пассивные `li`, а общий с генератором чек-листа).
- Цвета статусов в рамках тёмной темы и достаточный контраст.
- Имя ключа в `localStorage` и формат хранимого значения.
- Названия файлов скачивания.

## Проверка результата

- Тесты на чистые функции: переключение статусов по кругу; ключ отметки; применение отметок к собранному пакету (совпавшие сохраняются, лишние пропадают); подсчёт отчёта (по статусам, по фичам, «Готовность», только фичи с правилами, пустой пакет); CSV пакета (колонки «Статус» и «Комментарий», BOM, `;`, защита от формул в комментарии); CSV отчёта; загрузка из хранилища (пусто, битый JSON, неправильная форма); обрезка комментария.
- Руками: «Показать на примере», отметить статусы, перезагрузить страницу, отметки на месте; нажать «Собрать пакет» ещё раз, отметки не пропали; добавить правило для фичи без правил, отметки остальных фич не пропали; «Начать заново» с подтверждением; цифры отчёта на странице совпадают с обоими файлами; файлы открываются в Excel с правильными буквами; без горизонтальной прокрутки на 375px; статус различим без цвета.
- Первый экран и блоки `#tool`, `#bug`, `#rules` работают как раньше.
