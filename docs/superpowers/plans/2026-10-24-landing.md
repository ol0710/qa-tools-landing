# Лендинг «Набор маленьких QA-инструментов» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Одностраничный тёмный лендинг с работающим генератором чек-листа для тестировщика, выгрузкой в CSV для Excel и пользовательскими правилами.

**Architecture:** Один файл `index.html`: CSS в `<style>`, JS в `<script id="app">`. Логика (сопоставление, CSV, правила) в чистых функциях верхнего уровня без обращения к DOM, DOM-обвязка внизу скрипта под проверкой `typeof document !== 'undefined'`. Поэтому `tests/run.js` достаёт скрипт из `index.html` и гоняет функции в `node:vm` без браузера.

**Tech Stack:** HTML, CSS, vanilla JS. Тесты: `node tests/run.js` (Node 18+, только встроенные модули `node:fs`, `node:vm`, `node:assert`).

**Spec:** `docs/superpowers/specs/2026-10-23-landing-design.md`

## Global Constraints

- Один файл `index.html` прямо в `StartUp/landing`, стили и скрипт внутри.
- Без внешних библиотек, шрифтов и картинок из интернета. Шрифты только системные.
- Ванильный JS, без сборки.
- Данные пользователя не уходят из браузера.
- Нормально выглядит с телефона, без горизонтальной прокрутки.
- Тон: деловой, коротко, без воды. Не обещать «ИИ»: генератор работает по ключевым словам и шаблонам.
- Тёмная тема: фон около `#0f172a`, светлый текст, одна зелёная кнопка около `#22c55e`, достаточный контраст текста.
- Выгрузка: `.csv`, UTF-8 с BOM, разделитель `;`. В интерфейсе файл называется `.csv`, не `.xlsx`.
- Пользовательские правила только в `localStorage`; если он недоступен, страница работает без сохранения и один раз сообщает об этом.
- Коммиты в формате `эмодзи тип: описание на русском` (✨ feat, 🐛 fix, 📝 docs, ♻️ refactor, 🔧 chore), строка `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` в конце.

## Review Focus

- Описание или правило с `<script>` или `<img onerror=...>` не должно выполняться: всё выводится через `textContent`.
- Ячейка CSV с `;`, `"`, переводом строки или началом на `=`, `+`, `-`, `@` не ломает столбцы и не исполняется как формула в Excel.
- Повреждённый JSON в `localStorage` не ломает страницу: правила считаются пустыми.
- Пустое описание или только пробелы: ничего не выводится, показывается подсказка «Опишите фичу».
- Очень длинное описание (10 000 символов) обрабатывается мгновенно и не зависает.

## Структура файлов

- `index.html`: вся страница (CSS, разметка, скрипт).
- `tests/run.js`: запускает все проверки, печатает `OK`/`FAIL`, код выхода ненулевой при падении.

Пользовательский тип правила: `Rule = { keys: string[], group: string, checks: string[] }`. Пункт результата: `Item = { group: string, text: string }`.

### Task 2: Первый экран (заголовок, генератор, выгрузка CSV)

**Files:**
- Modify: `index.html` (секция `tool`, `<script id="app">`, CSS), `tests/run.js`

**Interfaces:**
- Consumes: Task 1: секция `#tool`, `loadApp()`, `check`.
- Produces (функции верхнего уровня в скрипте, объявлять через `function`, чтобы были видны из `vm`):
  - `normalize(text: string): string`: нижний регистр, `ё`→`е`, обрезка пробелов.
  - `getRules(): Rule[]`: встроенные правила, 8–12 тем по 4–8 проверок (форма, поле, пароль/password, загрузка файла, оплата, поиск и подобное).
  - `matchRules(description: string, rules: Rule[]): Rule[]`: правила, у которых хотя бы одно ключевое слово совпало с началом слова описания.
  - `buildChecklist(description: string, customRules: Rule[]): { items: Item[], usedDefault: boolean }`: встроенные плюс пользовательские, без повторов; общий набор из 5–8 пунктов в группе «Общие проверки», только если ничего не совпало; пустое или из пробелов описание даёт `{ items: [], usedDefault: false }`.
  - `toCsv(items: Item[]): string`: BOM `﻿`, заголовок `№;Группа;Проверка;Статус`, строки с номером, группой, проверкой и «не проверено», разделитель строк `\r\n`; ячейка с `;`, `"`, переводом строки или первым символом `=`, `+`, `-`, `@` экранируется (в кавычках, `"` удваивается, опасное начало получает перед собой `'`).

- [ ] **Step 1: Написать падающие проверки** в `tests/run.js`:
  - `buildChecklist('Форма входа с паролем', []).items` содержит группу, у которой название включает «парол» (без учёта регистра), `usedDefault === false`.
  - `buildChecklist('PASSWORDS reset', [])` срабатывает на ключ `password`; `buildChecklist('Пароля нет', [])` и `'Паролем'` срабатывают на «пароль» (поиск по началу слова, `ё`=`е`).
  - `buildChecklist('что-то странное', [])` даёт `usedDefault === true` и от 5 до 8 пунктов в группе «Общие проверки».
  - `buildChecklist('   ', [])` и `buildChecklist('', [])` дают `{ items: [], usedDefault: false }`.
  - `buildChecklist('x'.repeat(10000), [])` отрабатывает быстрее 200 мс.
  - `toCsv([{group:'А', text:'a;b "c"'}])` начинается с `﻿№;Группа;Проверка;Статус\r\n`, содержит `"a;b ""c"""`, статус `не проверено`.
  - `toCsv([{group:'А', text:'=1+1'}])` содержит `'=1+1`.
- [ ] **Step 2: Запустить `node tests/run.js`.** Ожидается FAIL (функций нет).
- [ ] **Step 3: Реализовать функции из Interfaces** в `<script id="app">`. Для сопоставления приводить ключ к основе (отрезать окончание у длинных слов), чтобы «пароль» совпадало с «пароля» и «паролем»; точный алгоритм на усмотрение исполнителя, он определяется тестами выше.
- [ ] **Step 4: DOM-обвязка и разметка** в секции `#tool`: `<h1>` деловой формулировки («Чек-лист по описанию фичи за секунды» или близкая), `<textarea id="desc">` с подсказкой «Описание фичи», `<button id="build">Собрать чек-лист</button> `, `<div id="result">`, `<button id="csv">Скачать для Excel (.csv)</button>`, скрытая до появления результата. Результат группируется по `group`, пункты со статичным пустым чекбоксом. Весь вывод через `textContent`/`createElement`, не `innerHTML` с пользовательскими данными. Пустой ввод показывает «Опишите фичу». Скачивание через `Blob` и временную ссылку `download="checklist.csv"`. Вызов обвязки под `if (typeof document !== 'undefined')`.
- [ ] **Step 5: Запустить `node tests/run.js`.** Ожидается: все OK.
