# Шаблон баг-репорта Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить на лендинг рабочую форму баг-репорта (текст для Jira и файл `.csv` для Excel) и убрать блок «Скоро».

**Architecture:** Чистые функции рядом с остальными в `<script id="app">` (уже есть общий `csvCell`), DOM-обвязка внизу под `typeof document !== 'undefined'`, проверки в `tests/run.js` через `loadApp()`.

**Tech Stack:** HTML, CSS, vanilla JS, `node tests/run.js`.

**Spec:** `docs/superpowers/specs/2026-10-24-bug-report-design.md` (и `2026-10-23-landing-design.md`).

**Изменение к спецификации (решение Ольги, 2026-10-24):** карточка «Калькулятор покрытия» тоже убирается, поэтому секция `#soon` удаляется целиком. Остальное по дизайну баг-репорта без изменений. Выгрузка для Excel это `.csv` (как у чек-листа), не настоящий `.xlsx`.

## Global Constraints

- Один файл `index.html`, стили и скрипт внутри; без внешних библиотек, шрифтов и картинок.
- Тёмная тема: переменные `--bg`, `--text`, `--muted`, `--accent`, `--card`, `--border` уже в `:root`.
- Вывод пользовательских данных только через `textContent` или `value`, не `innerHTML`.
- CSV: UTF-8 с BOM `﻿`, разделитель `;`, строки через `\r\n`; в интерфейсе файл называется `.csv`.
- Деловой тон, коротко. Без обещаний про ИИ.
- Нормально выглядит на 375px, без горизонтальной прокрутки, кнопки высотой от 44px.
- Коммиты `эмодзи тип: описание на русском`, строка `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` в конце.

## Review Focus

- Поле с `=`, `+`, `-`, `@` в начале любого поля (в том числе в многострочных шагах) не становится формулой в Excel: `csvCell` применяется к каждому полю.
- Шаги с переводом строки `\r\n` (вставка из Windows) нумеруются без пустых пунктов и без лишнего `\r`.
- Шаги из одних пустых строк считаются незаполненными.
- Поля из пробелов считаются пустыми, необязательные пропускаются в тексте.
- Кнопка «Скопировать» не падает, если `navigator.clipboard` недоступен.

## Структура файлов

- `index.html`: секция `#bug`, CSS, функции, обвязка; секция `#soon` удаляется.
- `tests/run.js`: новые проверки; существующие проверки про `#soon` и список секций обновляются (секции `soon` больше нет).

Тип данных: `BugFields = { title: string, env: string, steps: string, expected: string, actual: string, severity: string }`. `severity` одно из: `Блокирующая`, `Критичная`, `Значимая`, `Незначительная`, `Тривиальная`.

### Task 1: Функции баг-репорта

**Files:**
- Modify: `index.html` (скрипт), `tests/run.js`

**Interfaces:**
- Consumes: `csvCell(value: any): string` (уже есть в скрипте).
- Produces:
  - `bugSteps(steps: string): string[]`: строки шагов без пустых, обрезанные, разделитель `\r?\n`.
  - `isBugReportComplete(f: BugFields): boolean`: `true`, если заполнены `title`, `actual` и есть хотя бы один шаг (после обрезки пробелов).
  - `buildBugReportText(f: BugFields): string`: формат ниже.
  - `bugReportToCsv(f: BugFields): string`: BOM, `\r\n`, заголовок `Заголовок;Серьёзность;Окружение;Шаги;Ожидаемый результат;Фактический результат`, одна строка данных; шаги в ячейке нумерованы `1. …` через `\n`; каждое поле через `csvCell`.

Формат `buildBugReportText` (пустые `env` и `expected` пропускаются вместе со своими подписями):

```
Заголовок: <title>
Серьёзность: <severity>
Окружение: <env>

Шаги:
1. <шаг>
2. <шаг>

Ожидаемый результат: <expected>
Фактический результат: <actual>
```

- [ ] **Step 1: Написать падающие проверки** (по образцу `check(name, fn)`):
  - `bugSteps('a\r\n\r\n  b  \n')` равно `['a','b']`.
  - `isBugReportComplete` даёт `false` без заголовка, без `actual`, при шагах из одних пробелов и пустых строк; `true` при заполненных трёх.
  - `buildBugReportText({title:'T',severity:'Значимая',env:'',steps:'a\nb',expected:'',actual:'X'})` равно `'Заголовок: T\nСерьёзность: Значимая\n\nШаги:\n1. a\n2. b\n\nФактический результат: X'` (без строк `Окружение` и `Ожидаемый результат`); с заполненными `env` и `expected` они на месте, как в формате выше.
  - `bugReportToCsv` начинается с `﻿Заголовок;Серьёзность;Окружение;Шаги;Ожидаемый результат;Фактический результат\r\n`; ячейка шагов равна `"1. a\n2. b"`; `title:'=1+1'` даёт `'=1+1`; `actual` с `;` и `"` экранируется как в чек-листе.
- [ ] **Step 2: Запустить `node tests/run.js`.** Ожидается FAIL (`bugSteps is not a function` и подобное).
- [ ] **Step 3: Реализовать четыре функции** (одной обычной `function` верхнего уровня каждая, без новых зависимостей).
- [ ] **Step 4: Запустить `node tests/run.js`.** Ожидается: все OK.
- [ ] **Step 5: Commit** `✨ feat: функции баг-репорта для Jira и Excel`
